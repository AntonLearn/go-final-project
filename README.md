# Описание итогового проекта
Проект - веб-сервер, реализующий функции планировщика задач.  
Планировщик хранит задачи, каждая из которых содержит дату дедлайна и заголовок с комментарием. Задачи могут повторяться по заданному правилу: например, ежегодно, через какое-то количество дней, в определённые дни месяца или недели. Если отметить такую задачу как выполненную, она переносится на следующую дату в соответствии с правилом. Обычные задачи при их выполнении будут удаляться. В проекте создается база данных SQLite. Файл базы данных scheduler.db содержит таблицу scheduler. 

Функционал планировщика:
- добавить задачу;
- получить список задач;
- удалить задачу;
- получить параметры задачи;
- изменить параметры задачи;
- отметить задачу как выполненную.

Реализованы все дополнительные задания расширяющие возможности планировщика:
- возможность определять извне порт при запуске сервера;
- возможность применять все виды допустимых правил повторения задач;
- возможность определять путь к файлу базы данных через переменную окружения;
- возможность осуществлять поиск в списке задач по дате или по подстроке;
- возможность применять механизм аутентификации;
- возможность запуска планировщика из докер контейнера.

Дополнительно реализованы: 
- запись логов в файл вида [app_YYYY-MM-DD_hh-mm-ss.log],
- сброс логина как перед первым запуском планировщика, так и принудительно через соответствующий маршрут /api/signout,
- плавное завершение работы приложения.

В качестве пароля для входа в планировщик следует использовать пароль password.

В процессе инициализации планировщика данный пароль считывается из среды окружения из переменной TODO_PASSWORD, если он в ней определен. Также планировщиком из среды окружения считыввются порт и наименование БД, определенные в переменных TODO_PORT и TODO_DBFILE соответственно, если они в ней определены. 

Для реализации возможности запуска планировщика из докер контейера создан dockerfile выполняющий следующие инструкции:
- Этап сборки (builder):
-- задаёт базовый образ для этапа сборки — официальный образ Go 1.25.0 на базе Alpine Linux, 
-- устанавливает рабочую директорию внутри контейнера — /app,
-- копирует файлы зависимостей Go (go.mod и go.sum) из локальной директории планировщика в рабочую директорию контейнера (/app),
-- скачивает все зависимости планировщика согласно go.mod,
-- копирует всю локальную директорию планировщика в рабочую директорию контейнера (/app),
-- компилирует Go‑приложение в статически связанный бинарный файл todo-app;
- Финальный этап (runtime):
-- запускает новый этап сборки на базе минимального образа Alpine Linux, не содержащий Go‑компилятора,
-- обновляет список пакетов (update) и устанавливает ca-certificates — сертификаты CA, необходимые для работы с HTTPS, отключив кэширование пакетов,
-- устанавливает рабочую директорию в /root/,
-- копирует скомпилированное приложение (todo-app) из этапа builder в текущую рабочую директорию (/root/),
-- копирует статические веб‑файлы (например, HTML, CSS, JS) из этапа сборки в директорию ./web внутри финального образа,
-- объявляет, что контейнер будет слушать порт 7540,
-- устанавливает переменные окружения для планировщика: 
--- TODO_PORT — порт, на котором запускается приложение,
--- TODO_DBFILE — путь к файлу базы данных,
--- TODO_PASSWORD — пароль,
-- задаёт команду, которая будет выполнена при запуске контейнера - запуск бинарного файла todo-app. 

Для сборки образа докер контейнера выполнить команду:
    docker build -t todo-scheduler .

Для запуска собранного докер контейнера выполнить команду:
    docker run -d  --name todo-scheduler-containe \
        -p 7540:7540 -e TODO_PORT=7540 -e TODO_DBFILE=scheduler.db \
        -e TODO_PASSWORD=password todo-scheduler
